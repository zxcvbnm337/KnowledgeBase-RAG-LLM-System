# 简历用项目描述 · 本地知识库 RAG 智能问答系统

> 全部表述均可对应到项目实现：`config_data.py`（参数）、`retrieval.py`（检索链路）、
> `file_history_store.py`（分层记忆）、`tests/eval_retrieval.py`（检索评测）。

---

## 一、项目描述（简历项目标题下第一段，可直接使用）

针对高校学生查询教务与培养信息时资料分散、检索效率低、答复口径不一的痛点，基于 Streamlit + LangChain
+ Chroma 搭建本地 RAG 智能问答系统，支持多格式文档入库与流式多轮问答。针对传统 RAG 存在的上下文膨胀
与知识库外问题幻觉作答两大缺陷进行优化：动态限制对话上下文条数，解决 Token 溢出问题；优化相似度判定
阈值，大幅提升库内与库外问题的区分度，实现知识库外问题精准拒答，保障学生获取信息的准确可靠。

---

## 二、应用场景（面试开场讲这段）

本项目面向高校学生的信息查询场景，从学生的日常处境出发。

每学期开学，学生总要反复确认几件小事：这门选修课算不算通识学分、挂科之后是补考还是重修、请假超过几天
需要学院审批、奖学金评定究竟看哪几项。答案分散在培养方案（PDF）、课程表（Excel）、学生手册（Word）与
各类通知文件之中，格式不一、版本又多，问同学得到的答复还常常是过期的。为了一条规定把几个文件翻一遍，
是这个场景里最真实的困扰。

系统将这些资料统一解析入库，学生用自己的话提问即可得到答案，例如「大二下通识课还差几个学分」「补考没过
要重修吗」。对于食堂菜单、宿舍分配、往年考题这类知识库未覆盖的问题，系统明确拒答并说明资料范围，而不是
给出一个听起来很像真的答案。之所以强调这一点，是因为校园场景的容错率很低——若依据错误信息安排选课或
错过申请时间，代价往往无法挽回。**明确的「无法回答」，优于看似合理的错误回答。**

## 三、应用技术

| 层 | 技术 |
|---|---|
| 语言 / 框架 | Python 3.13、LangChain 0.3（LCEL 链式编排、`RunnableWithMessageHistory`）、Streamlit |
| 向量检索 | Chroma 1.x（本地持久化）、`text-embedding-v4` 嵌入、`gte-rerank-v2` 交叉编码重排、L2 距离归一化为相似度 |
| 大模型 | 通义千问 `qwen3-max`（对话与摘要压缩分模型配置，以控制成本）、DashScope SDK |
| 文档解析 | pypdf（逐页抽取）、python-docx（段落与表格）、openpyxl（逐工作表）、csv；多级编码回退 |
| 工程化 | python-dotenv 配置治理、MD5 内容去重、分层记忆 JSON 持久化（兼容多种历史格式）、零依赖断言测试 |
| 评测 | 命中率（Hit@K）、平均排名（MRR）、库外拒答准确率、库内误拒率、分数判定间隔 |

## 四、四条亮点（每条约 90 字）

**1｜分层对话记忆：以短期原文与长期摘要双层管理对话历史**
对话历史采用双层结构管理：短期层保留最近消息原文，保证指代可解析；长期层将更早内容压缩为摘要，与旧
摘要合并后持久化。注入上下文因此稳定在可控区间，实测连续十二轮后，首轮提到的关键信息仍可准确回溯。

**2｜检索链路重构：召回、重排与阈值门控三段分离**
检索拆分为召回、重排与门控三段：召回保留距离并归一化为相似度，重排以交叉编码模型精排，门控依据最高分
判定是否作答，未达阈值即拒答、不调大模型。重排异常时自动降级为向量排序，链路不中断。

**3｜多格式文档解析：覆盖六类业务文档并统一异常语义**
解析层覆盖 PDF、Word、Excel、CSV、Markdown 与纯文本六类格式：PDF 按页抽取，Word 连表格一并提取，
Excel 按工作表转文本，编码多级回退，异常统一收敛为可读提示。

**4｜可量化评测：为检索参数建立可比基线**
内置标注问题集，覆盖库内与库外两类提问，输出命中率、平均排名、拒答准确率与分数间隔，使阈值调整、模型
更换均有可比基线。配套自动化测试覆盖三模块，不依赖模型接口，可随时执行验证回归。

## 五、项目成果

系统在长对话下不再受上下文长度限制，首轮给出的关键信息在十几轮后仍可准确回溯；知识库外的问题稳定拒答，
不再编造答案。六类文档均可直接入库，扫描件与损坏文件也会给出可读提示。项目由九个模块、约一千行代码
构成，配套近百项自动化测试，可随时本地验证。

## 六、面试追问预备

- **为何不直接采用现成的 RAG 框架？** 现成封装未暴露检索分数，无法据此实现拒答；本项目需要一条可观测、可评测的检索链路。
- **语料规模较小，命中率是否具备参考价值？** 语料仅含少量片段，命中率已接近上限、区分度不足，因此对外主要陈述的指标是两类分数的判定间隔。
- **分层记忆是否会丢失信息？** 会取舍细节，但保留事实性内容；摘要生成失败或结果为空时保留全部原文，以完整性优先。
- **后续优化方向？** 回答引用溯源、短期窗口按 token 而非条数控制、切分策略改按标题层级。
